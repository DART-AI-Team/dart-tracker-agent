# DART Ingestion Module

이 모듈은 DART(오픈다트)로부터 공시 데이터를 실시간으로 감지하고, 수집하여 로컬 데이터베이스에 캐싱(적재)하는 역할을 담당합니다.

---

## 🏗️ 폴더 및 파일 구조

```text
app/ingestion/
├── README.md               # 모듈 문서
├── __init__.py             # 패키지 진입점 (Facade/조립기)
├── builder.py              # [1회성] 초기 2년치 과거 데이터 적재 배치
└── modules/                # 하위 비즈니스 로직 모듈
    ├── database.py         # DB 연결 및 세션 관리
    ├── crud.py             # DB 데이터 등록 및 존재 여부 조회 (check_exists 등)
    ├── parser.py           # DART 공시 데이터 정제 및 파싱
    └── observer.py         # 실시간 신규 공시 감시 (DART API 폴링)
```

---

## 🎯 설계 의도 (Design Intent)

### 1. 로컬 캐싱을 통한 무비용 적재 (Zero-Cost Ingestion)
* **API 비용 세이브**: 수집 단계에서는 LLM API 호출이나 임베딩(Vector) 변환을 전혀 수행하지 않고, 순수 메타데이터와 본문 텍스트(Raw Text)만 DB에 적재하여 **수집 요금을 0원**으로 유지합니다.
* **API 호출 제한 우회**: DART API의 일일 호출 제한(10,000회)을 우회하기 위해 로컬 DB를 원본 데이터의 캐시 저장소로 활용합니다.

### 2. 패키지 캡슐화 (`__init__.py` 활용)
* 외부(`app/main.py`)에서 `modules/` 디렉토리 내부의 복잡한 파일 구조나 파일명을 몰라도 되도록, `__init__.py`에서 하나의 단순한 통합 래퍼 함수(`start_ingestion_service()`)로 조립하여 노출합니다.
* 이를 통해 모듈 간 결합도를 낮추고 자유로운 내부 리팩토링이 가능하도록 설계했습니다.

### 3. 실시간 감시와 일회성 배치의 격리
* **`observer.py`**: 서비스 러닝 타임(상시) 동안 백그라운드로 작동하며 신규 공시를 감시합니다.
* **`builder.py`**: 서비스 배포 초기 단계에서 단 1회만 실행되어 과거 2년치 데이터를 DB에 빌드하는 독립 배치 프로세스입니다.
